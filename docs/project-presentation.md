# R Fitness：3 分鐘專案介紹

[開啟展示網站](https://r-fitness-web.onrender.com/) · [示範帳號與操作步驟](../README.md#線上體驗) · [驗證紀錄](verification-2026-10-01.md)

以下口述稿搭配畫面約 3 分鐘，實際時間依語速與操作速度調整。面試前先開啟網站、登入會員，另準備教練營收畫面與 README，讓時間用在說明功能。主講段落使用專案事實；個人負責範圍請依實際經驗補充。

## 0:00–0:25｜問題與使用者

**畫面：首頁。**

「R Fitness 是一個健身課程預約平台。它處理的是從找教練、選時間，到報名與管理剩餘堂數的完整流程。會員可以依專長與時間選課，教練則能管理自己的課程和查看報表。專案的重點是讓前台操作、後端規則和資料庫紀錄保持一致。」

## 0:25–1:05｜展示預約與退堂

**畫面：找教練 → 課程 → 報名成功 → 我的課表。**

「這裡可以先認識教練，也能在課表依日期與訓練專項篩選。選好課程後，會員確認報名，系統會使用一堂額度，並將課程加入個人課表。取消報名後，額度會回補，原始紀錄仍然保留。堂數不足時可以購買方案；目前購買是模擬流程，只建立紀錄與額度，沒有串接真實金流。」

## 1:05–1:35｜技術架構

**畫面：README 架構圖。**

「前端使用 React、TypeScript 與 Vite，透過 Axios 呼叫 Express API。後端使用 TypeORM 存取 PostgreSQL，主要資料包含會員、教練、課程、購買與報名紀錄。前端、API 和資料庫部署在 Render，雲端展示資料與本機分開。頁面採按需載入，營收圖表只在進入該頁時下載，主 JavaScript 檔由約 839 KB 降至 413 KB。」

## 1:35–2:15｜資料規則與權限

**畫面：會員剩餘堂數，再切換已準備好的教練後台。**

「剩餘堂數不是另外維護一個數字，而是用購買總堂數減去未取消報名數，即時計算。報名前會檢查課程、重複報名、剩餘額度和名額；取消則標記取消時間，因此能保留紀錄並回補堂數。權限由後端執行：先驗證 JWT、查出會員，再檢查教練角色。修改課程還要核對課程所有者，不能只靠前端隱藏按鈕來保護資料。」

## 2:15–2:45｜測試與具體修正

**畫面：GitHub Actions 或驗證紀錄。**

「品質驗證包含 69 項後端合約測試、12 項開發版與 13 項正式建置版瀏覽器測試，也在空白資料庫和重新安裝依賴的環境跑過。案例涵蓋扣堂、退堂、角色權限與重新整理。我也能用營收計算說明回歸測試的價值：同一會員報兩堂課，參與人數是一人，但營收應算兩筆報名；這個差異已修正並加入測試。」

## 2:45–3:00｜目前邊界與下一步

**畫面：回到課表或首頁。**

「目前已完成可操作的展示流程。若要承接正式營運，下一步會補上預約併發時的交易與鎖定、資料庫 migration，以及真實金流與付款通知驗證。」

## 現場操作提示

| 時機 | 操作 | 可展示的結果 |
| --- | --- | --- |
| 開始前 | 登入 README 的示範會員，記下剩餘堂數；提前開好教練後台與 Actions | 避免等待免費 API 喚醒或現場切換帳號 |
| 選課 | 從教練頁或「選課與預約」找一堂未來課程 | 搜尋、日期／專項篩選、每頁 6 堂與分頁 |
| 預約 | 點「報名」並確認，再點「查看我的課表」 | 成功訊息、預約紀錄、剩餘堂數減 1 |
| 取消 | 在「我的課表」找到該課並確認「取消報名」 | 取消紀錄保留、剩餘堂數加 1 |
| 教練 | 使用另一個瀏覽器或無痕視窗登入教練，預先開啟營收頁 | 避免共用同一登入狀態；比較報名筆數與不重複人數 |

公開示範帳號共用；已取消的同一堂課不能再次報名，重複演練請選另一堂課。若課程不在本週，可切換課表日期或列表查看。付款不需輸入信用卡；示範交易不會真實扣款。

## 延伸追問備忘

| 問題 | 依現行實作可回答的重點 |
| --- | --- |
| 為什麼不直接儲存剩餘堂數？ | 從購買與有效報名紀錄推導，避免同時維護額度欄位與紀錄。資料量增加後可評估索引或彙總；目前不是帳務總帳。 |
| 取消會刪掉資料嗎？ | 不會。`cancelled_at` 標記取消；計算使用堂數時排除它。現行規則不允許重新報名同一堂已取消課程。 |
| 有防止超賣嗎？ | 一般請求會檢查名額，但檢查與寫入尚未包進具鎖定的交易，不能宣稱已解決同時搶最後名額的競態。後續需搭配交易、適當鎖定與併發測試。 |
| JWT 裡的角色可信嗎？ | 後端驗證 token 後，依 ID 從資料庫取得會員，再用資料庫角色判斷權限；前端路由限制只是操作體驗的一部分。 |
| 營收是實際付款嗎？ | 不是。依報名建立月份，以未取消報名筆數乘方案平均單堂價格後向下取整；不重複會員數另外統計，並非金流實收或已完成課程收入。 |
| 效能改善證據是什麼？ | 主檔建置大小約減少 51%，有正式建置版按需載入測試。這是檔案大小比較，不能直接說網頁載入速度快了 51%。 |
| 測試是否都打真實 API？ | 後端合約與主要會員／教練流程使用隔離資料庫；部分介面與分頁案例使用模擬回應。兩者的驗證目的不同。 |
