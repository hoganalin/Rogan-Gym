# Core Platform

## Purpose

R Fitness 平台的核心域能力：帳號與角色、教練瀏覽與報名、堂數方案購買、會員課表管理、教練後台。這份規格描述「做什麼事」；視覺與互動細節見 [`frontend-experience`](../frontend-experience/spec.md)，領域詞彙見 [CONTEXT.md](../../../CONTEXT.md)。

## Requirements

### Requirement: User 可升級為 Coach，但當前登入 session 不會自動取得新角色
系統 SHALL 讓 USER 角色送出升級申請後，資料庫的角色立即變成 COACH，但**當前瀏覽器 session 持有的 JWT 不會被更換**——JWT 的 role 是登入當下就固定寫進去的。升級成功後 SHALL 登出並要求重新登入，讓新的登入流程簽發帶有 COACH role 的新 token。

#### Scenario: 升級成功後前端不假裝目前 session 已經是教練
- **GIVEN** 一個 USER 角色的會員送出「成為教練」表單並成功
- **WHEN** 升級 API 回應成功
- **THEN** 前端登出目前 session、導向登入頁，而不是原地把記憶體裡的 `user.role` 改成 COACH

### Requirement: 課程報名採一人一堂一筆記錄，取消是軟刪除
一個 User 對同一堂 Course 最多只能有一筆報名記錄（不論是否已取消）；取消報名 SHALL 標記取消時間、保留記錄，不刪除資料列。

#### Scenario: 已取消的課程不能重新報名
- **GIVEN** 某會員曾報名某堂課後取消
- **WHEN** 該會員再次嘗試報名同一堂課
- **THEN** 後端回傳「已經報名過此課程」的錯誤，前端把這段錯誤原文顯示在彈窗裡

### Requirement: 剩餘堂數即時計算，不是資料庫欄位
會員可用堂數 SHALL 由「總購買堂數 − 未取消的報名數」即時算出，不儲存快取值。

#### Scenario: 取消報名會讓可用堂數立即回升
- **GIVEN** 會員剩餘堂數為 7（已用 5、購買 12）
- **WHEN** 會員取消一筆未取消的報名
- **THEN** 重新查詢課表時剩餘堂數變為 8，不需要任何額外的「退堂數」操作

### Requirement: 教練月營收由未取消報名數換算，不是課程本身的價格
教練的月營收 SHALL 以「當月未取消的報名數 × 全站平均單堂價格」計算，平均單堂價格 = 全部堂數方案總價 ÷ 全部堂數方案總堂數（先乘後無條件捨去一次）。月份參數用英文小寫月份名，只能查伺服器目前這一年。

#### Scenario: 營收依報名建立時間歸屬月份，不是課程上課時間
- **GIVEN** 一堂課的上課時間是 9 月，但會員是在 8 月底報名的
- **WHEN** 教練查詢 8 月營收
- **THEN** 這筆報名計入 8 月，不是 9 月

### Requirement: 教練檔案的個人照片網址為必填且需為 https
教練檔案儲存 SHALL 要求 `profile_image_url` 為非空字串且以 `https` 開頭，即使剛升級的教練這個欄位原始值是 `null`。

#### Scenario: 剛升級的教練第一次存檔前端就要求填照片網址
- **GIVEN** 一位剛升級成教練、`profile_image_url` 仍是 `null` 的使用者開啟個人檔案表單
- **WHEN** 使用者不填照片網址直接送出
- **THEN** 表單擋下送出（HTML `required`），不會等後端 400 才知道漏填

### Requirement: 技能標籤是全站共用資源，不屬於任何單一教練
Skill SHALL 對所有教練共用可見、可編輯，後端不做擁有者範圍限制；任一教練都可以新增或刪除任何技能標籤。

#### Scenario: 教練刪除另一位教練建立的技能標籤
- **GIVEN** 教練 A 建立了技能標籤「壺鈴」
- **WHEN** 教練 B（未曾建立過這個標籤）在自己的技能標籤頁刪除「壺鈴」
- **THEN** 刪除成功，這個標籤從全站消失（包含教練 A 的檔案上也不再顯示）
