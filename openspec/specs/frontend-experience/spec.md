# Frontend Experience

## Purpose

R Fitness 前端（會員／教練預約平台）的視覺與互動規格：深色重訓風主題、捲動進場效果、教練搜尋與篩選、會員課表的多種檢視方式。後端 API 與資料模型不在此規格範圍內（見 [CONTEXT.md](../../../CONTEXT.md)）。

## Requirements

### Requirement: 深色主題視覺語言
系統的所有公開與登入後畫面 SHALL 使用統一的深色配色（底色 `#08090a`、卡片 `#121316`、邊框 `#22242a`）與橘色主色（`#f4501e`），不使用漸層按鈕。

#### Scenario: 登入前後導覽列樣式一致
- **GIVEN** 使用者瀏覽任一公開頁面
- **WHEN** 頁面載入完成
- **THEN** 導覽列背景為深色、主色按鈕（如「加入會員」）為橘底黑字，不含漸層

### Requirement: 教練列表可依技能篩選、依姓名或簡介搜尋
系統 SHALL 讓使用者在教練列表頁用文字搜尋（比對姓名／簡介／技能）與技能標籤多選篩選，全部在前端完成，不對 `GET /coaches` 新增查詢參數。

#### Scenario: 選擇技能標籤後列表即時過濾
- **GIVEN** 教練列表已載入完成
- **WHEN** 使用者點擊某個技能標籤（例如「壺鈴」）
- **THEN** 只顯示技能包含「壺鈴」的教練卡片，頁面右上角的計數同步更新為「符合數 / 總數」

#### Scenario: 找不到符合條件的教練
- **GIVEN** 使用者輸入的搜尋文字或選取的技能標籤沒有任何教練符合
- **WHEN** 過濾結果為空陣列
- **THEN** 顯示「找不到符合條件的教練」的提示區塊，而不是空白畫面

### Requirement: 會員課表支援週曆／月曆／清單三種檢視
系統 SHALL 讓會員在「我的課表」頁面切換週曆、月曆、清單三種檢視，三者共用同一份 `GET /users/courses` 回傳的 `course_booking` 陣列，不重複打 API。

#### Scenario: 切換檢視不重新整理頁面
- **GIVEN** 會員已進入「我的課表」頁面
- **WHEN** 點擊「月曆」分頁
- **THEN** 畫面立即切換成月曆格線，不觸發新的 API 請求，已取消的報名以灰色樣式與「已取消」標籤呈現

#### Scenario: 清單檢視是進入頁面的預設檢視
- **GIVEN** 會員剛登入並進入「我的課表」
- **WHEN** 頁面完成首次渲染
- **THEN** 預設顯示清單檢視（可立即看到課程名稱與「取消報名」操作，不需要先切換分頁）

### Requirement: 捲動進場效果不能造成內容永久不可見
主視覺、統計數字、卡片區塊的捲動進場動畫（GSAP）SHALL 在使用者關閉系統動畫偏好（`prefers-reduced-motion: reduce`）時完全不執行，元素維持最終可見狀態；資料非同步載入時，動畫必須綁在資料就位之後才初始化，避免抓到空的 DOM。

#### Scenario: 關閉動畫偏好時內容仍完整可見
- **GIVEN** 使用者的系統設定為 `prefers-reduced-motion: reduce`
- **WHEN** 使用者開啟首頁
- **THEN** 統計數字直接顯示最終值、教練卡片與方案卡片的透明度為 1，不會停留在 `opacity: 0`

#### Scenario: 統計數字的 count-up 目標值不受重複初始化影響
- **GIVEN** 開發模式下 React StrictMode 讓特效初始化邏輯執行兩次
- **WHEN** 第二次初始化執行
- **THEN** 動畫仍以資料原始數值（例如教練總數 100）為目標，不會因為讀到第一次動畫過程中的中間值而跑向錯誤的目標
